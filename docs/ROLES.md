# DogBuddyCn 角色体系设计（三层指挥链）

> 版本 v1.0 ｜ 2026-10-14 ｜ 用户拍板「管理员负责系统、主管属于员工、管理员命令主管、主管命令员工」
> 本文是角色职能的权威定义；架构落地见 `ARCHITECTURE-v2-ROLES.md`。

## 1. 三层定位

```
管理员 (Administrator) ── 负责「系统」
        │  下达目标 / 划分项目 / 配置资源 / 审批高危 / 任免主管
        ▼
主管 (Supervisor) ── 属于「员工」，负责「项目」
        │  拆解目标 / 派活 / 盯进度 / 汇总回报 / 裁决员工提问
        ▼
员工 (Worker) ── 负责「执行」
```

| 角色 | 归属 | 定位 | 汇报对象 |
|---|---|---|---|
| **管理员** | 系统层（人类运营者） | 系统总负责人；可多个（分管系统不同域）。定战略目标、创建项目、任免主管、系统配置、审批不可逆操作、收主管汇总 | 人类（owner） |
| **主管** | **员工层**（AI 管理者） | 项目负责人；一个主管管一/多个项目。拆目标、派活、盯进度、组织共享频道协作、汇总回报、裁决提问 | 管理员 |
| **员工** | 员工层（AI 执行者） | 执行者；「程序员」是其中一种，可扩展工种。接任务、干活、按时回报、遇阻提问 | 主管 |

## 2. 权限矩阵

| 能力 | 管理员 | 主管 | 员工 |
|---|:---:|:---:|:---:|
| 系统配置 / 自升级 / 管理员账号管理 | ✅ | ❌ | ❌ |
| 创建项目 / 任免主管 | ✅ | ❌ | ❌ |
| 工位 · 任务 · 群组 · 上下文管理 | ✅ 全局 | ✅ **仅本主管项目内** | ❌ |
| 派活给员工（下发任务） | ✅ | ✅ 项目内 | ❌ 不能派活 |
| 执行任务（文件 / shell / 搜索 / 代码） | ❌ 不亲自干 | 必要时可 | ✅ |
| 审批高危（不可逆命令） | ✅ | 项目内普通操作 | ❌ |
| 记忆（memory 读写） | ✅ 全局 | ✅ 项目内 | ✅ 本工位 |
| 汇报 | → 人类 | → 管理员 | → 主管 |

## 3. 指挥链信息流（四向）

| 流向 | 内容 | 通道 |
|---|---|---|
| 管理员 → 主管 | 目标 / 资源 / 优先级 | 指令下发（`supervisor.command`） |
| 主管 → 员工 | 任务派发 | 工位队列投递（scoped 管理工具） |
| 员工 → 主管 | 结果 / 提问 | 上报事件（`worker.report`） |
| 主管 → 管理员 | 汇总 | 汇总事件（`supervisor.digest`） |

- **共享频道** = 项目协作空间，**主管是群主**（组织项目内工位协作）。
- 汇报不再"员工直达管理员"，而是**逐级收敛**：员工结果默认上报该项目主管，主管合并后报管理员。
  （单管理员 + 无主管的退化场景：保持直连，见架构 v2 §迁移路径。）
- **审批逐级**：员工触发的审批先到项目主管（普通操作可就地放行），不可逆 / 越项目边界 → 升级管理员。

## 4. 主管的形态（关键定义）

**主管 = 一个装了「管理工具」的工位（window.role = `supervisor`），作用域 = 其所属项目。**

- 复用现有工位机制：串行队列、持久会话、上下文压缩、工作区、检查点全套不变。
- 差异只有两点：① 工具集多出**作用域受限的管理工具**（派活 / 建任务 / 管本项目工位）；
  ② 调用管理工具时 scope = 自己负责的项目集（管理员是 system 级全局）。
- 一个主管可负责多个项目；项目 `owner_supervisor_id` 指向该项目的主管工位。
- 主管挂项目根为工作区（吃 Batch 7 项目层），必要时可亲自下场干一小段活。

## 5. 与既有决策的关系

| 决策 | 关系 |
|---|---|
| 决策 5「暂不做多用户」 | **不冲突**——这是角色层级（管理域），不是租户隔离 |
| 决策 4「通知最小集」 | 主管承担合并汇报，天然减少噪声；火警 / 决策点仍直达管理员 |
| 决策 10「共享频道协作」 | 主管是群组组织者与组长 |
| Batch 4 审批托管 | 路由改**逐级**：员工 → 主管 → 管理员 |
| Batch 7 项目层 | 项目 owner = **主管**（非管理员） |
| Batch 8 迭代调度 | 迭代执行者 = **主管**（拉项目团队跑轮次、汇报进展） |

## 6. 角色与资源的归属模型

```
管理员(system scope)
  └── 项目 project（owner = 主管）
        ├── 主管工位 (role=supervisor, workspace=项目根)
        ├── 员工工位 × N (role=worker_*, workspace=项目根/子目录)
        └── 共享频道 group (组长 = 主管)
```

- 资源（工位 / 任务 / 群组 / 项目内记忆）都挂 `project_id`，scope 由此推导。
- 无项目归属的遗留资源 → 自动归入「默认项目」，避免迁移断档。
